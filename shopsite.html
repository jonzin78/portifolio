ショッピングサイト

Category EC / Web Application
Tools React / JavaScript / CSS / Vite / React Router / Firebase / Firestore
Period 約3週間

Overview

JavaScript・Reactの授業課題として制作した ショッピングサイトです。

商品一覧、商品詳細、お気に入り、 カートなどのECサイトで使用される 基本的な機能を実装しました。

HTMLとCSSだけで構築する静的サイトではなく、 Reactを利用してユーザー操作に応じて UIが動的に変化するWebアプリケーションとして 開発しています。

Project Purpose

この制作では、JavaScriptの基礎だけではなく、 Reactを利用したコンポーネント開発や state管理について理解することを目的としました。

また、実際のECサイトで利用されている 商品表示、カート、お気に入りなどの機能を 自分で実装することで、 フロントエンド開発の流れを 実践的に学ぶことを目指しました。

Engineering

このサイトではReactをベースに コンポーネント指向で開発しています。

商品カードやヘッダーなど、 複数のページで使用するUIを コンポーネントとして分割しました。

これにより、同じUIを何度も記述することを避け、 再利用性と保守性を意識したコード構成にしています。

Component Design

Reactでは、ページ全体を一つのコンポーネントとして 作るのではなく、役割ごとにコンポーネントを分割しました。

例えば商品カードでは、 商品名・価格・画像などの情報を Propsとして受け取り、 同じコンポーネントを複数の商品に 再利用できるようにしています。

このような設計にすることで、 商品数が増えた場合でも UI側のコードを大きく変更する必要がありません。

State Management

React Hooksの useState を使用して、 ユーザー操作によって変化するデータを管理しました。

例えばカートに商品を追加した場合、 stateを更新することで 商品一覧やカート内の商品数などの UIをリアルタイムで更新しています。

「ユーザーが操作する」 →「stateが変化する」 →「ReactがUIを再レンダリングする」 というReactの基本的な仕組みを 実際のアプリケーションで学びました。

useEffect

useEffect を利用して、 コンポーネントの表示時に必要なデータを取得したり、 LocalStorageに保存されている情報を 読み込む処理を実装しました。

Reactのレンダリングと 外部データの取得・保存処理を 分離して考えることで、 副作用を適切に管理する方法を学びました。

React Router

ページ間の移動には React Router を使用しました。

商品一覧ページから商品詳細ページへ移動したり、 お気に入りページやカートページへ移動できるように ルーティングを設定しています。

商品詳細ページでは商品IDを利用して、 選択された商品に対応する情報を 表示する仕組みを実装しました。

Data Flow

商品データとUIを分離することを意識して 開発しました。

商品情報をJSONやFirestoreから取得し、 Reactのコンポーネントへデータを渡して 商品カードとして表示しています。

データの取得処理と表示処理を分離することで、 データの保存場所が変わった場合でも UI側への影響を少なくできる構成を意識しました。

JSON Data

制作初期では商品データを JSON形式で管理しました。

商品画像、商品名、価格、カテゴリー、 商品説明、販売状態などをオブジェクトとして管理し、 JavaScriptから読み込んで表示しています。

HTMLに商品情報を直接記述するのではなく、 データとUIを分離することで、 商品追加時のコード変更を少なくしています。

Firestore

開発を進める中で、 商品データをFirebase Firestoreへ移行しました。

Firestoreからデータを取得し、 React側で商品情報を表示することで、 外部データベースとフロントエンドを 接続する経験をしました。

これにより、 「フロントエンドで表示するだけ」ではなく、 データベースからデータを取得して UIへ反映するという Webアプリケーションの基本的な流れを学びました。

Favorite Function

商品カードにお気に入り機能を実装しました。

ユーザーがハートボタンをクリックすると、 対象の商品をお気に入りリストへ追加・削除できます。

お気に入り情報は LocalStorage に保存しています。

そのため、ページをリロードしても 保存したお気に入り情報が消えないようにしています。

Cart Function

ECサイトの主要機能である カート機能も実装しました。

商品をカートへ追加すると、 カート内の商品数が更新され、 カートページで商品の一覧を確認できます。

また、商品の数量変更や削除にも対応し、 商品価格と数量から 合計金額をJavaScriptで計算しています。

カート情報についてもLocalStorageを使用し、 ブラウザをリロードした場合でも カートの状態を維持できるようにしました。

CRUD Concept

カートやお気に入り機能の実装を通して、 CRUDの基本的な考え方についても理解しました。

商品を追加するCreate、 情報を取得するRead、 数量を変更するUpdate、 商品を削除するDeleteという データ操作の基本的な流れを経験しました。

Asynchronous Processing

Firestoreなど外部からデータを取得する処理では、 非同期処理についても学びました。

データが取得されるまでの時間を考慮しながら、 取得したデータをReactのstateへ反映して UIを更新する処理を実装しました。

この経験から、 Webアプリケーションでは 「データがすぐに存在する」とは限らないことを理解し、 非同期処理を意識してコードを書くようになりました。

UI / UX

機能だけではなく、 ユーザーが直感的に操作できるUIも意識しました。

特に商品一覧では、 商品画像・商品名・価格を 見やすく整理し、 「商品を見る」 「お気に入りに追加する」 「カートに入れる」 という操作が分かりやすくなるように ボタンの位置や余白を調整しました。

Responsive Design

PCだけではなく、 スマートフォンでも利用できるように レスポンシブデザインを実装しました。

CSS Media Queryを使用して 画面幅に応じて商品カードのレイアウトや ボタンのサイズ、余白などを調整しています。

ECサイトではスマートフォンから 商品を見るユーザーも多いため、 小さい画面でも操作しやすいUIを意識しました。

Development Environment

開発環境には Vite を使用しました。

Viteによる開発サーバーを利用することで、 コードを変更した際に すぐブラウザへ反映しながら開発しました。

コーディングには Visual Studio Code を使用しています。

Git / GitHub

ソースコードの管理には Git / GitHub を使用しました。

開発中の変更内容をコミットして保存し、 GitHub上でプロジェクトを管理しています。

Gitを使用することで、 コードを変更する前の状態へ戻したり、 開発履歴を確認したりすることができます。

Deployment

完成したWebアプリケーションは Firebase Hostingを利用して インターネット上へ公開しました。

ローカル環境で開発するだけではなく、 実際にWeb上へデプロイするところまで経験したことで、 開発から公開までの基本的な流れを学びました。

Challenges

制作で特に難しかったのは、 Reactのstate管理と LocalStorageを組み合わせた部分です。

商品をカートへ追加するだけではなく、 数量を変更したときに 合計金額や商品数など複数のUIを 正しく更新する必要がありました。

また、LocalStorageからデータを読み込んだ際に、 React側のstateと保存されているデータの 状態が一致しない問題もありました。

データの流れを一つずつ確認しながら 処理を分けて実装することで問題を解決しました。

Debugging

開発中には、 ボタンをクリックしてもUIが更新されない、 カートの商品数が正しく表示されない、 LocalStorageのデータが期待通りに 保存されないといった問題も発生しました。

Consoleでエラーを確認したり、 stateの値を確認したりしながら、 一つずつ原因を特定して修正しました。

この経験を通して、 エラーが発生したときに すぐコードを書き換えるのではなく、 「どこで値が変わっているのか」 「どの処理が実行されているのか」 を確認することが重要だと学びました。

What I Learned

この制作を通して、 JavaScriptとReactを使った Webアプリケーション開発について 実践的に学ぶことができました。

特に、HTML・CSSだけで制作するWebサイトと、 JavaScript・Reactを使用したWebアプリケーションでは、 考える必要のある部分が大きく異なることを実感しました。

UIを作るだけではなく、 「どのデータをstateとして管理するのか」 「どのタイミングでデータを取得するのか」 「どのコンポーネントがデータを持つべきなのか」 など、アプリケーションの構造を考える力が身につきました。

Reflection

今回の制作で一番感じたことは、 Webサイトを作ることと Webアプリケーションを作ることでは、 必要になる考え方が大きく違うということです。

HTMLとCSSを使ったWebサイト制作では、 見た目やレイアウトを考えることが中心でしたが、 Reactを使った今回の制作では、 ユーザーの操作によってデータがどのように変化し、 その変化をどのようにUIへ反映するのかを 常に考える必要がありました。

特にカートやお気に入り機能では、 一つのデータを変更すると 他の部分の表示にも影響するため、 stateやデータの流れを理解することの 重要性を実感しました。

また、最初はエラーが出たときに どこを修正すればよいのか分からないこともありましたが、 Consoleのエラーを確認し、 データの中身や処理の流れを一つずつ確認することで 自分で原因を探せるようになりました。

今回の制作を通して、 「コードを書く力」だけではなく、 「問題が起きたときに原因を考えて解決する力」 の重要性も学びました。

今後は、今回学んだReactやFirebaseの知識を活かして、 ログイン機能、検索・絞り込み機能、 商品登録機能、決済機能など、 より実際のサービスに近い Webアプリケーションの開発にも挑戦したいです。

Summary

本制作では、 React・JavaScriptを中心に ECサイトを想定したWebアプリケーションを制作しました。

商品一覧・商品詳細・お気に入り・カートなどの UI実装だけではなく、 React Hooksによるstate管理、 React Routerによるルーティング、 LocalStorageによるデータ保存、 Firestoreによるデータ管理、 Firebase Hostingによるデプロイまで経験しました。

フロントエンド開発に必要な 「UIを作る」「データを扱う」 「状態を管理する」「公開する」 という一連の流れを経験できたことが、 この制作で得られた大きな成果です。
